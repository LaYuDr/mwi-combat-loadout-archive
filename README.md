# 配装助手

在游戏原生配装详情下保存多个场景子方案，例如“远程单人”“远程多人”“远程迷宫”。选择方案后，对照当前原生配装，列出需要手动修改的项目并高亮原生槽位。

## 行动配装记忆

在生活项目或战斗地点的行动详情中选择配装后，助手会立即记住；下次打开同一项目（包括刷新页面后）自动恢复。选择“无配装”也会保存，未选过的项目沿用游戏原有默认值。同一战斗地点的不同难度共用这份记录。

只恢复弹窗里的配装选项；加入队列、立即开始和实际装备仍由玩家操作。配装改名不影响记忆；已删除或不适用的配装不会恢复，页面会提示重新选择。

记录按站点、角色和项目分开保存在 localStorage 的 `mwi-layu:action-loadouts:v1:` 独立键下，不改已有子方案或其他插件数据。多个标签页各自保留当前选择，下次打开项目时读取最近保存的记录。存储失败会显示提示，游戏的手动选择仍可使用。这些记录不包含在子方案导出备份中。

## 子方案使用

1. 打开游戏的“配装”，选择一个原生配装，战斗、各项生活技能及“所有技能”均可。
2. 在游戏原生控件中调好装备、技能顺序、触发条件、食物与饮料。
3. 在“子方案”点击“＋”，输入名称并“保存”。可在同一父配装下保存多个方案。
4. 点击方案标签，在高亮槽位下方查看目标值；触发条件通过“条件 N 项”展开。点击“差异”可展开完整“当前 → 目标”清单并“定位”。助手只提示，不自动点击、装备或发送游戏请求。
5. 手动修改原生配装后，差异约每 650ms 更新，已一致的高亮与目标标记消失。提示“配装已一致”不代表角色已经穿戴；是否装备仍由玩家操作原生按钮。

界面采用 E 方案：解释段落移除，差异清单默认收起，新建表单按需显示。标题旁的“更新”保存当前所选方案；右键或长按约半秒打开对应方案的菜单，提供“改名／移除／结束对比／导出全部／导入备份”。键盘可使用 Shift+F10；没有方案时可对“＋”使用相同操作导入备份；移除后“撤销”直接出现。未能定位的差异会自动展开文字清单，槽位恢复后会重新显示标记。

**保存来源是当前打开的原生配装，不是角色此刻的实际穿戴。** 如需先把实际穿戴复制到原生配装，请自行使用游戏的“导入当前配置”，确认游戏操作的影响范围后，再保存子方案。

支持国际服及国服的 `milkywayidle.com/game`、`milkywayidlecn.com/game`（含 www）；不再运行于战斗模拟器。子方案支持战斗、各项生活技能及“所有技能”配装；行动配装记忆支持生活和战斗项目。

## 保存范围

- 装备种类、各槽位与空槽，生活及“所有技能”配装包含全部 10 个生活工具槽位；指定/最高强化模式；最高强化模式下，同一装备的不同强化等级不判为差异。
- 战斗配装：5 个技能槽位及顺序，每个技能的完整触发条件，包括显式零、空条件与未知扩展字段。
- 战斗配装：3 个食物和 3 个饮料槽位、各消耗品的完整触发条件。生活配装比较 3 个饮料槽位；“所有技能”配装按原生页面仅比较装备及工具。快照保留全部原始字段，未显示的槽位不产生差异指引。
- 完整原生配装 JSON 副本保留在子方案中；库存数量、技能因角色成长变化的等级不是切换目标。

子方案按当前站点、角色 ID 和原生配装 ID 隔离，父配装改名不会改变关联。数据库为独立 IndexedDB `mwi-layu-loadout-scenes`，不读取或清除旧模拟器存档或其他插件数据。

同名保存不会覆盖。选择子方案后，可改名、明确确认后更新快照，或移除并在当前页面撤销。方案菜单中的“导出全部”备份当前父配装的有效子方案，不含已移除记录；“导入备份”须为同一站点、角色、父配装，完整校验后一次添加，同名且快照相同的记录跳过，同名不同内容报错，不覆盖现有方案。

读取失败或游戏结构变化时停止保存与完成判断；无法定位的槽位仍显示文字清单。触发条件翻译优先使用游戏资源，未知名称回退为标识，并可展开查看完整数据。子方案功能只读 React 数据，不调用原生操作函数。行动配装记忆仅观察行动详情实例的配装选择更新，并通过 `setState` 恢复该选项，不调用开始、排队、装备等游戏操作函数。读取兼容 DOM 标记及当前 React 根容器；DOM 无标记时仅沿所属页面分支查找精确节点，跳过无关 DOM 分支，不读取旧 alternate 树，扫描设有上限。

## 本地开发

Node.js 20 及以上，无构建依赖。

```sh
npm run check
node ../银河奶牛本地开发服务/source/control.mjs start loadout
```

开发加载器地址：`http://127.0.0.1:4178/mwi_combat_loadout_archive.dev.user.js`。

**原模拟器开发加载器需要重新安装生成的新版**，以更新为游戏站点的匹配权限；仅刷新旧模拟器页不能完成迁移。只启用正式版或开发版中的一种，安装后刷新游戏，再打开原生配装详情。

源码由 `source/build.cjs` 统一生成正式包、元数据、加载器、runtime 和校验和。请求本地入口会重新构建，响应无缓存，构建失败返回 503。服务代码改动后重启 loadout 服务；`npm run dev` 是前台调试入口，使用前需停止同名后台服务。

## 文件

- `source/scene_core.js`：完整快照校验、装备哈希解析、差异计算。
- `source/game_adapter.js`：只读当前原生配装、翻译和槽位定位。
- `source/action_memory.js`：生活与战斗项目的配装记忆、独立存储和临时选项恢复。
- `source/scene_store.js`：独立数据库、作用域隔离、事务、修订冲突保护、备份。
- `source/app.js`、`source/scene.css`：原生页面内嵌界面、差异跟踪和高亮。
- `source/dev_loader.js`、`source/dev_server.cjs`：4178 本地开发链路。
- `source/release_current_version.mjs`、`release.config.json`：现有发布链路。

为保留现有安装与发布渠道，仓库名、文件名和用户脚本 namespace 暂时沿用历史标识；业务已独立重写。

## 验证与发布

```sh
npm run check
npm run test:browser
npm run release:dry-run
```

浏览器检查使用独立临时 Chrome 配置、合成原生配装夹具和合成数据，另包含生活与战斗配装记忆、刷新恢复、角色隔离、已删除配装与存储失败检查。子方案检查验证完整字段、差异、手动修正、重载、命名、更新、撤销、备份、角色及父配装隔离、跨页冲突、键盘焦点和窄屏。不连接个人浏览器、不操作真实游戏；不代表 Tampermonkey 或真实游戏完整验收。

Playwright 路径和 Chrome 路径可分别通过 `MWI_ARCHIVE_PLAYWRIGHT`、`MWI_ARCHIVE_CHROME` 指定。从 Codex 启动 macOS 本机 Chrome 须先经沙箱外执行审批。

本地实现不自动发布。后续发布遵循 [发布流程](docs/RELEASING.md)，普通构建不写历史包。

打开原生装备或技能选择列表时，助手会以蓝色内描边高亮该槽位对应的目标候选项。指定强化等级时同时核对等级；目标不在当前列表中时保留槽位指引，不自动选择或滚动列表。

## 安装与活跃统计

沿用其他助手的统计设置，正式安装包默认开启，可在原生配装详情中的“统计”关闭；开发加载器不统计。数据范围和服务端待配置项见 [安装与活跃统计](docs/USAGE_STATISTICS.md)。
